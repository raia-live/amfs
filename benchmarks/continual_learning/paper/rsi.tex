\begin{abstract}
\noindent
An agent that runs for months inherits a world that changes under it. Policies are rewritten,
dependencies re-pinned, workflows changed, and nobody tells the agent, so it acts on what used
to be true and every later session that reads the same thing fails the same way. Scaling such
agents is a self-improvement problem: the system has to notice that its knowledge is wrong,
draft a correction, test it, release it to a small share of traffic first, and keep a record,
without a person in every loop. SenseLab is an engine built for that. Outcome evidence changes
what agents act on (level~0); a repair agent built into the engine drafts corrections that must
pass a stand-in
replay, the customer's own replay and a live canary before they ship, reversibly (level~1); the
loop reads its own history when it drafts again (level~2); and its record trains the next model
and the repair prompt (level~3). This paper is the first measurement of such a loop. We evaluate
the whole engine on a continual benchmark where the correct action for a task class changes
conditionally at episode 30 of 100, so half the class needs the new rule and half still needs
the old one. On four held-out seeds, two agent models and two task families (12,800 episodes,
analysis frozen before the run), SenseLab takes the new action first in 45\,\% of moved-half
episodes, against 25\,\% for the frontier model alone, 32--36\,\% for three pgvector baselines
and 40\,\% for a 24k-token context window; it wins 8--11 of 16 paired cells against each
baseline, and no pairing survives Holm correction. It holds unchanged work at 100\,\% and loses
the kept half to the context window by 24 points at a third of the cost. In ten-agent,
200-episode cells the moved half rises from 37\,\% in the first fifty post-change episodes to
75\,\% in the last fifty. In an exploratory 400-episode run with the traffic the canary rule is
sized for, five of eight canaries decided: four passed and shipped, and one wrong fix failed at
88\,\% recurrence against 10\,\% before it reached \code{main}. Along the way the benchmark
found twelve defects in the loop's evidence path, all fixed in production and re-measured on the
same protocol. That record is the paper's main contribution: a self-improving system is only as
trustworthy as its evidence path, and a retrieval benchmark would have seen none of these.
\end{abstract}

\section{Introduction}

The hard part of scaling agents is longevity. A model that solves a task today is deployed into
an operation that runs for months. The policies it applies get rewritten, the dependencies it
pins get audited, the workflows it follows get changed by people who never tell it. Its tasks
never repeat exactly, so nothing can be memorised. The failure that matters is that it acts,
confidently, on what used to be true, and does so again on every session that reads the same
thing. A static model with a static context degrades in such a world, and a person in every
loop does not scale.

The alternative is a system that improves its own operation from its own results, which is
also the thing to be nervous about. A self-modifying system amplifies its errors as readily as
its corrections. A model that drafts fixes from failure evidence will draft wrong ones, and a
wrong fix written into what every agent reads damages every session at once. The question is
what discipline makes self-improvement safe enough for production: evidence before proposal,
proof before release, a small exposure before full exposure, reversibility after, and an audit
trail throughout.

SenseLab is an engine built on that discipline, and this paper measures it. Its loop has four
levels (\S\ref{sec:engine}). At level~0, every session's outcome is attributed to exactly what
the agent read and did, and that evidence changes what the next session acts on. At level~1, an
entry that was validated and now fails is a \emph{regime shift}; the engine's repair agent drafts a
correction on a branch, with a manifest of the runs it claims to repair and the runs it must not
break, and the correction must pass a stand-in replay (Tier~1), the customer's own agent
replaying the case set (Tier~2) and a live canary on a hashed share of sessions (Tier~3) before
it ships, reversibly. At level~2, the loop's history on an entry is evidence for its next draft.
At level~3, the record trains the next model and the repair prompt. The claim is that a
correction may only change behaviour after it has been tested on the runs it claims to repair
and shown no worse than the control arm on live traffic, and that a system built this way
recovers faster than one that can only demote what failed, while shipping fewer wrong
corrections than one that ships on a passed test.

We ask, on a benchmark that knows the true rule before and after every change, whether the whole
engine recovers faster and further than the frontier model alone, than three vector-store
baselines, than a context window carrying the cell's entire history, and than its own
ablations; whether it damages what still worked; what it ships; and what it costs. We call the
whole system SenseLab throughout. The ablations that switch parts of it off appear in one
attribution table and nowhere else.

\paragraph{What this version is.} This is the first version with the confirmatory read: seeds
37, 41, 59 and 73, both agent models, run once after the analysis code was tagged, with every
endpoint and test fixed beforehand (\S\ref{sec:confirmatory}). The development-seed sections
(\S\ref{sec:results}) are kept because the preregistration committed to reporting every
prediction, met or falsified. Most of the early predictions were falsified, by defects in the
loop's evidence path that the benchmark found and that were fixed in production between runs;
\S\ref{sec:findings} is the record of that. The fleet-1 confirmatory cells are read and final.
The ten-agent fleet-10 cells ran twice, because the first run exposed the last of the findings,
and the second run is the read reported here.

\section{The engine under test}
\label{sec:engine}

Everything measured is production code on the SenseLab SaaS, run against a dedicated Enterprise
account. No constant below was tuned for this study; each is quoted from the deployed source.
The harness never decides anything. It seals sessions through the public API, and the loop's own
scheduler proposes, tests, gates and ships.

\paragraph{Level 0: outcome learning.} An agent calls \code{briefing} and \code{retrieve}
before acting, \code{record\_action} and \code{record\_attempt} as it goes, and
\code{commit\_outcome} when the task ends. The sealed trace carries the exact read set, and the
outcome is attributed to it: an entry read by a run that failed after a recorded attempt against
it is charged the failure, and an entry read by a clean success is credited. Entries carry an
evidence status (\code{untested}, \code{validated}, \code{contested}, \code{discredited}).
\code{retrieve} returns, with the hits, per-action priors (won/lost here on similar tasks) and a
recommendation mode: \code{act}, \code{explore} (assigned per agent, so peers explore different
actions) or \code{escalate}. Level~0 alone is the row ``SenseLab $-$ repair loop'' in
Table~\ref{tab:attribution}.

\paragraph{Regime shift and situation.} A regime shift is an entry validated at least three times
that now fails: a sealed failure whose read set contains such an entry, or a recorded failed
attempt against it. An entry that was never validated cannot have shifted; the guard that
separates the two cases was the third defect this study found (\S\ref{sec:findings}). The same
entry can be right in one situation and wrong in another, so the agent labels each session with
an \code{attributes.situation}, and the service resolves the label to the agent's canonical
situation (a stemmed-token rule, Jaccard $\geq 0.5$, with an embedding second stage at cosine
$\geq 0.75$). The shift, the proof set and the canary are all scoped to the situation. A shift
proposes a fix automatically (\code{auto\_propose}, per agent).

\paragraph{Level 1: proposal.} SenseLab's repair agent, a platform-side component of the engine
with a 50k-token budget per draft, reads the failing runs, the entry and the loop's history on that entry, and writes either a corrective
entry (lever \code{knowledge}) or a conditional procedure with conditions, steps and a verify
(lever \code{procedure}) on memory branch \code{repair/<fix>}. It attaches a manifest: the runs it
predicts it repairs, the runs it must not break, and an expected prevention (0.5 by default). A
\code{code} lever is handed off and never auto-shipped.

\paragraph{Tier 1: stand-in replay.} A stand-in model re-runs each manifest case with the branch
as memory and tool calls answered from the recorded run. Fidelity is the share of steps answered
from the record; a test below the agent's fidelity floor (0.5) does not count as a pass. A test
is \code{passed}, \code{failed} or \code{inconclusive}.

\paragraph{Tier 2: customer replay.} The fix's case set (HMAC-signed cases) is delivered to the
customer's agent, which re-runs them on the branch and seals the results; the service grades each
replay against the case's expectation. For a regime fix the case set is the run the shift fired
on, up to three more of the situation's failed runs (the fix must turn them into successes) and
up to three of its passed runs (the fix must not break them). A case no judge graded is graded on
the outcome the replay reports and, since the \code{post-clean-success} cut, on its attempts: a
success reached after a recorded failed attempt fails the case (finding 9).

\paragraph{Tier 3: canary.} A passed fix opens a canary. Sessions are bucketed by
$\mathrm{sha256}(\mathit{fix}{:}\mathit{session})$; a share \code{pct} reads from the branch,
writes always go to \code{main}, and the trace is stamped with its branch. \code{decide()}
requires both arms to reach \code{min\_outcomes} graded runs, where a graded run is one in the
fix's situation or one that read an entry the fix is about (cut \code{post-canary-ni}; before it,
situation only: finding 11). The canary is the loop's harm gate. The replay tiers prove the
benefit on the failing runs; live traffic has to show the change does not make the agent worse on
the runs the old rule still served. It passes when the canary arm recurs significantly less
(one-sided two-proportion $z$-test, $p<0.05$), or when the one-sided 95\,\% Newcombe upper bound
on canary$-$control recurrence is under a 10-point margin with the failure still live in control.
It fails when the canary arm recurs significantly more. Before \code{post-canary-ni} the primary
asked for a significant improvement, and no canary ever passed. The benchmark maps the production
defaults (10\,\%, 20 outcomes, 14 days) to \code{pct}=50, \code{min\_outcomes}=8 and a timeout
of 60 sessions (the cell horizon, 100 or 200, from amendment~(v) on), evaluated every 5 graded
sessions. One canary per agent at a time.

\paragraph{Ship, verify, revert.} Policy \code{auto\_after\_canary} merges a passed canary's
branch into \code{main}; \code{auto\_after\_replay} (the ``$-$ canary'' ablation) merges on a
passed Tier~2. A feedback contract holds a fix if fewer than 80\,\% of recent traces carry
provenance. Prevention is verified over the following window, and a regressed fix is rolled
back to the pre-fix versions. Continuous judges (a two-tier \code{gpt-5-mini}$\to$\code{gpt-5}
rubric pack) grade sealed traffic and open incidents, the second producer of proposals.

\paragraph{Level 2: the loop reads its own history.} Every fix event on an entry (proposed,
tested, replayed, shipped, regressed, rolled back) is written back as evidence on that entry,
and the repair agent's next draft on the same entry reads it. Whether the loop stops repeating
its own mistakes is the two-change protocol of the flagship experiment, not yet run.

\paragraph{Level 3: the record trains the model and the improver.} The traces the loop produces,
including the repair trajectories and the cases it pinned, are a training set. Managed Models
(\code{senselab-s1}) are distilled from them and served with the same evidence record as their
memory (\S\ref{sec:results}). The repair prompt itself is A/B tested across proposals, scored by
proven fixes per prompt. Only the first rung of the first of these is measured in this version.

\section{Benchmark and protocol}
\label{sec:prereg}

\paragraph{Preregistration.} Hypotheses, arms, metrics, seeds, the dev/confirmatory split and
the analysis freeze were registered before the first run (\code{HYPOTHESIS\_RSI.md}, tag
\code{prereg-rsi-v1}). Every change since is a dated amendment, (a) through (ab), appended below
the original with a prediction and what would falsify it. Seeds 11 and 23 are the development
seeds; 37, 41, 59 and 73 run once, after the analysis code is tagged
\code{analysis-freeze-rsi}. Engine changes made between runs are recorded with their deploy cut
to the second, and every result carries its cut.

\paragraph{Environment.} Two of the benchmark's ten task families, both with tool-using agents
and oracle-graded outcomes: \code{support} (a helpdesk agent with account, order and export
tools; 15 issue classes) and \code{ci-fix} (an agent repairing failing CI on a repository; 10
failure classes). Every task instance is generated, never repeated, with random identifiers
(\code{opaque\_ids}) so nothing can be read off an id. 100 episodes per cell, 300 distractor
entries in every store, retry budget 3, one agent identity per cell, GPT-5.5 at low effort, and
a post-episode reflection note in every arm that has a store.

\paragraph{Change set C.} At episode 30 a subset of classes changes conditionally: the correct
action moves for instances with one attribute value (the \emph{moved half}) and stays for the
others (the \emph{kept half}). Half of post-change tasks come from changed classes. Set C was
written after the pilots showed that on an unconditional change (set A) outcome learning alone
recovers nearly everything a maintainer who knew the rule would (finding 4). The only place a
written rule can beat demotion is where demotion has no signal, because the entry is still right
half the time. Set C is registered by hash; its remaining eight families are written blind.

\paragraph{Systems.} Frontier alone (no store); context window (every prior note and outcome of
the cell in the prompt, most recent first, 24k tokens); pgvector (bge-small, cosine top-5 over
notes); pgvector + rerank (the cross-encoder SenseLab serves); pgvector + outcomes (notes, LLM
consolidation every 5 episodes, a per-entry win/loss counter shown to the agent); and SenseLab
(\S\ref{sec:engine}, policy \code{auto\_after\_canary}). Mem0 and Zep are not run; an earlier
grid covers them~\cite{senselab-cl}. The ablations, SenseLab $-$ canary
(\code{auto\_after\_replay}) and SenseLab $-$ repair loop (policy \code{review}, proposals never
approved), appear in Table~\ref{tab:attribution} only.

\paragraph{Endpoints.} First-attempt success on the moved half after the change (primary);
first-attempt success on the kept half and on unchanged classes (collateral damage); episode
success and escalation; the fix lifecycle (proposed, Tier~1, Tier~2, canary, shipped, reverted);
and cost. Infrastructure errors are excluded from rates and reported. Intervals are cell-level
bootstrap (2,000 resamples). With four cells per system on the development seeds they are wide,
and they are shown so that no reader mistakes a dev-seed difference for a result.

\subsection{What level 1 did: the gating record}
\label{sec:gating}

The repair loop did not move the outcome endpoints on these seeds. What it did is refuse. Every
fix it drafted went through the proof set and, if that passed, the live canary, and on the
current cut nothing shipped: the proof rejected the drafts that restated or flipped the rule
wholesale, and the canary held the rest because the failure they were written for was no longer
live. A loop that ships only what it can prove, and only against a failure it can still observe,
is slower than one that ships what looks right. The record below is what that slowness bought and
cost; the confirmatory seeds re-measure it on the same protocol (\S\ref{sec:confirmatory}).

\paragraph{What the loop did.} On the current cut the loop proposed 13 fixes in the four SenseLab
cells, 8 from regime shifts. Four passed Tier~1 (8 inconclusive), 4 passed Tier~2 and 7 failed
it (one open), and none shipped, because no canary decided before the cell ended. Three canaries
were running at episode 100. Two had 2/8 and 4/8 canary-arm runs graded against the floor. The
third was fully graded (18 canary-arm and 31 control-arm runs) and still had no verdict: at
6\,\% against 10\,\% recurrence the one-sided bound on the difference was 13 points against a
margin of 10. With a 10\,\% control recurrence the bound falls under the margin at about 15
graded runs per arm if the canary never recurs, about 30 if it recurs at 6\,\%, and about 50 if
it recurs as often as control; a 100-episode cell supplied 18 and 31 to its best canary. Two cuts
earlier the same protocol passed 15 of 24 at Tier~2 and the no-canary ablation shipped 11 of 16;
on the previous cut the ablation shipped 2 of 17; on this cut it shipped none of 14 (Tier~2: 0
passed, 13 failed). With 27--43 episodes per half per family, none of the outcome differences
between the arms is a difference.

\paragraph{What the proof rejects.} Three cuts earlier, hand-coding the fix text against the
true change, 20 of the 24 regime fixes that passed their proof set encoded an unconditional flip
(``always $Y$'') where the change was conditional (``$Y$ when $a$, else $X$''); on \code{ci-fix},
19 of 19. The proof graded a replay on the outcome it reported, or on a judge whose rubric passes
a recovered run, and an agent with a retry budget recovers, so a wholesale flip passed every case
it could. Since the \code{post-clean-success} cut a proof case passes only on a clean success,
whatever grades it. On that cut Tier~2 failed 19 of the 23 regime fixes that reached it; on the
current cut, with the repair agent also handed the situation's passing runs, it failed 15 of 17:
4 on a kept case (a flip broke the half the old rule still holds for), 10 on a moved case only
(the old rule in better words did not repair the half that moved), 1 on a pre-change case. The
two that passed, both in canary and neither shipped, are a wholesale flip on \code{ci-fix} (the
opposite of the true condition) and a retry ladder on \code{support} that branches on what has
already failed, not on the app version the change turned on. Their replays succeeded cleanly
anyway, because the replaying agent read the rule and did not follow it into the wrong action. A
proof pass is therefore necessary and cannot by itself certify a conditional when the agent's
compliance with an entry is partial; that is what the live canary is for.

\paragraph{What the drafts say now.} Amendment (v) changed the draft: the repair agent is shown
the situation's passing runs and asked for the condition that separates them from the failing
ones. P11(a$'$) asks whether at least half of the regime drafts whose proof set holds a kept case
state a condition. Coded by the author against written instructions (amendment (y); every text,
the coding and the key are in the package), 21 of the 37 such drafts on this cut (57\,\%) state
an input-dependent branch: met. The split by class is the finding. On \code{ci-fix} 11 of 14
drafts are conditional and every one names the true variable (whether the PR touches
\code{legacy\_sdk/}). On \code{support} 9 of 23 are conditional, and they branch on what is
visible in the ticket (platform or plan), not on what the world changed on: the plan is named by
2 of 7 export-timeout drafts, the issuer country by 0 of 8 card-declined drafts, the app version
by 0 of 6 notification drafts. The drafter writes conditions where the evidence puts the variable
in front of it, as file paths in a diff do, and writes the salient attribute where it does not.
The confirmatory fleet-1 drafts (39, same sheet, same key) read the same way: 27 of 39 (69\,\%)
state a condition; on \code{ci-fix} 20 of 28, 17 of them on the PR's files; on \code{support} 7
of 11, none on the true variable.

\section{What the loop taught us about itself}
\label{sec:findings}

The preregistration promised to report every prediction, and Table~\ref{tab:ledger} is that
report. The findings below are what a benchmark that knows the true rule found in a shipped
self-improvement loop: twelve defects and two properties of the problem. All twelve were fixed
in production with their deploy cuts recorded, eleven between runs and re-measured on the same
protocol, the twelfth (finding~14) inside the exploratory run of amendment~(ab). The last four
were found in the fleet-10 runs, two of them from the loop's own read record while the
confirmatory fleet-10 cells were running. None of these failures is specific to our engine; the
evidence path is where such systems fail.

\begin{enumerate}[leftmargin=1.6em, itemsep=0.35em]
\item \textbf{The loop was never reached.} (Pilots 5b--5g.) Incidents open at three failing
verdicts on one behaviour cluster. A fresh agent's judges had graded nothing, so no incident
opened and no fix was proposed in 60 episodes. The regime-shift producer, an entry validated
$\geq 3$ times that now fails, is the producer a memory can drive without judges, and every
result here rests on it.
\item \textbf{Sealing stalled under load.} A lock on the seal path held sessions open under the
grid's concurrency. Fixed (\#780/\#781) before any reported run.
\item \textbf{A first-exposure failure is not a regime shift.} (Amendment (k), pilot 5k; P1
falsified 3/3.) The shift producer fired on entries that had been read, not validated, so the
first failure of a never-tested entry opened a canary that could grade nothing: it compared
recurrence of a failure the control arm had never had. The guard now requires validation in the
situation.
\item \textbf{On an unconditional change, demotion recovers almost everything.} (Amendment (l);
P4.) A scripted maintainer writing the true rule five episodes after the change beat outcome
learning alone by 2.5 (\code{support}) and 4.2 (\code{ci-fix}) points on 60 episodes of set A.
That is the ceiling a repair loop can reach on such a change, and it is small. Change set C was
written so that demotion has no signal: the entry is still right on the kept half.
\item \textbf{A regime fix had nothing to be proved against.} (Seam 4, \#793; P6 met on the
ablation.) Case sets were built from judge verdicts; a fix drafted from a shift had none, so
Tier~2 could not be asked. The manifest's runs now seed the case set, and a judge-less case is
graded on the replay's outcome.
\item \textbf{The agent spells one situation ten ways.} (Seam 5, \#794; P7 recall 0.71, purity
0.92 against 0.80/0.90 predicted; seam 5b, \#796, P7$'$ falsified: 0.40/0.67.) A canary scoped
to a situation graded 2 of 15 in-situation runs because the agent labelled the same situation
\code{csv export timeout}, \code{data export error}, \code{large export failing}. A server-side
canonical resolves labels by stemmed tokens. The embedding second stage added for recall lowered
it and merged \code{ci-fix} classes (\code{format check failure} $\sim$ \code{audit check
failure} at 0.79); it is left on by decision, with its cost stated.
\item \textbf{A running canary swallowed every later fix's replays.} (Seam 7, \#795; P8 met.)
The router bucketed a Tier~2 replay session like any other, so a replay for fix $B$ sealed during
$A$'s canary was stamped onto $A$'s branch, counted in $A$'s arm, and reported \code{missing} to
$B$. Replays are now re-stamped onto their own branch and excluded from every canary tally.
\item \textbf{The loop drafted fixes from its own tests.} (Seam 8, \#797; P10 met.) A Tier~2
replay that failed on a fix branch read to the regime pass as the entry failing on \code{main}.
13 of 40 fixes on the \code{post-seam5b} cut were drafted from a replay, in chains, and one
replay's spelling became a canonical that four served runs then joined. Replays are no longer
traffic at the seal: no judge, no identity, no shift. (The first cut of this rule also excluded
the labelled copy of a served inference, which is traffic; an automated reviewer caught it
before merge.)
\item \textbf{The proof graded the wrong signal.} (Amendment (s), \#797; P9(b) falsified
20/24.) An outcome-graded case passed a recovered success, so an unconditional flip passed a
proof set built to catch it (\S\ref{sec:gating}). A case now passes only on a clean success,
with no recorded failed attempt, and the change is dated by the case, not the deploy, so earlier
case sets keep their semantics.
\item \textbf{Who grades the proof.} The clean-success rule of finding 9 applied to a case no
judge graded. Here 174 of 175 proof cases carry a judge, the benchmark's own frozen rubric, which
says by design that ``a run that failed one or more attempts before succeeding is a PASS''. The
proof tier inherited the coarse signal through the judge as well as through the outcome, and
finding 9's fix reached one case in 175. Of the 555 case replays run since the
\code{post-seam5b} cut, 479 passed, and 116 of those passes (24\,\%) carry a recorded failed
attempt. The correction carries the clean-success requirement on every case built for a regime
fix, whatever grades it. It shipped as the \code{post-clean-success} cut, and P11 is read on
that cut (\S\ref{sec:pending}).
\item \textbf{The canary grades by canonical situation, and the agent's declarations fragment.}
(Found in the fleet-10 run of \S\ref{sec:posthoc}; fixed in \#799.) A canary counts exposure
(sessions the router stamped to its arm) but graded only runs whose canonical situation equalled
the fix's. The agent declares its situation per run in its own words, often carrying the very
condition the change turns on (``pip audit requests pin with legacy sdk''); situation identity
folded one agent's 56 declarations to 10 canonicals, and the fixes carried others. So 0--8 of
16--30 exposed runs per arm were graded, and no canary decided in 200 episodes with ten agents.
The one whose declarations were stable reached 25/30 graded, found 12\,\% against 17\,\%
recurrence, and timed out, because the rule waited for a significant improvement. Corrected
after approval (amendment~(v), cut \code{post-canary-ni}): the canary grades runs in the fix's
situation or that read an entry the fix is about, and its primary is non-inferiority, because
the canary is the harm gate on a change the replay tiers already proved. Canonical merging was
not done; it changes situation identity for every customer with the opposite failure mode.
Re-measured (\S\ref{sec:posthoc}): graded runs rose from 0--27\,\% of exposure to 12--55\,\%,
four of nine canaries reached the floor, none decided.
\item \textbf{The fix was written where no agent could read it.} (Found 2026-09-30 in the
loop's own read record, after the confirmatory fleet-10 cells had run half their length with
canary-arm reads of the fix still at zero; fixed in amfs-internal \#802, cut
\code{post-canary-visible}.) Every write the repair loop makes (the correction on the fix's
branch, the corrective entry, the merged version once a fix ships, the contrast lessons) is
authored by the platform itself, as \code{amfs-server}. The visibility rule that keeps one
customer's agents from reading another's admitted an entry only when its author was one of the
caller's own agents, or a room member or the platform on a room's shared path. The platform's own
writes on an agent's ordinary path matched neither clause, so for every user-scoped API key they
did not exist. The reuse record stores, for every retrieve, read and search, which entry version
the session was served; joined version-exactly to the arm stamps on the sealed traces, it gave
the count. Of 25,875 reuse events over the two days before the fix, none was on a
platform-authored entry; no causal entry or read in any canary arm since the \code{rsi-e2b-c6}
cut was the fix's; the 230 contrast lessons on \code{main} had never been read. On a canary
branch the effect was worse than absence: the corrected key's branch version replaced the
agent's version of the key and was then dropped, so what the canary arm received was the key's
deletion. Every canary in \S\ref{sec:posthoc} compared an arm that had lost the entry with an arm
that still had the old one. The rule now admits a platform-authored entry on a path where one of
the caller's own agents has written, never account-wide; on the benchmark account that covers
318 of 318 corrections and 168 of 168 corrective entries. One limitation survives: the loop
writes a correction at $0.8\times$ the confidence of the version it replaces (floor 0.3) while
the benchmark's agents read at a confidence gate of 0.5, so of the 31 shipped fixes that carry a
correction, 20 sit below the gate on \code{main}, visible but not read there; on the canary
branch the pin carries the correction to the head regardless. The re-measurement (the four
\code{rsi-conf-e2b} cells, six canaries) was the first time a canary arm read its fix: 17 reads
in 23 graded canary-arm sessions for the one fix that rewrote an existing key
(\code{repo-readme-ci}, 74\,\%), and 0, 0, 1, 1, 1 for the five that wrote a new key. P13$''$
was falsified (1, 1, 8.5, 0.5) and P16 pooled was 20 of 108 graded sessions, 19.8\,\%, at the
falsification line. That one fix was read and five were not is finding~13.
\item \textbf{The loop's own replays discredited the fix before the arm could read it.} (Found
2026-09-30 in the read record of the cells above; fixed in amfs \#455, cut
\code{post-replay-evidence}; the confirmatory fleet-10 cells re-run on it, amendment~(aa).)
Five of the six corrections were discredited by outcome evidence within 1--24 minutes of being
written, two before their canary's first session. Traced on \code{b2b656c5}: the correction was
written at 09:00:09Z at confidence 0.78; the loop's three Tier~2 replays ran over the next
minute and all ended in \code{success}, so Tier~2 passed, but two of them carried two recorded
attempts each, and each failed attempt charged the entry it had read with a failure. At $n=0$
one charge takes 0.78 to 0.41; by 09:01:14Z the posterior was under the discredit threshold, 74
seconds before the canary started. The pin of \#454 does not pin a discredited entry, so the arm
the branch existed to treat was never served it: 0 reads in 74 sessions. \code{2ae2f0e0} went
the same way and then failed its canary on an arm that had never read it (2 recurrences in 8
against 0 in 22); a failing verdict is not read-gated, so the gate rejected a treatment that was
never applied. None of the 30 earlier canary corrections had ever been discredited, because
nobody could read them; making the fix readable is what exposed this seam. The same replays had
written 425 \code{lesson-contrast-replay-*} entries onto \code{main} since 2026-09-26, each
naming a correction under test as the entry to avoid. The engine already held the rule that a
replay is not traffic where the loop grades (finding~8); \#455 completes it on the memory side.
A replay's outcome writes no outcome row, and a discredited entry is pinned on its own branch all
the same, because the canary can only test what the arm read.
\item \textbf{The loop's failed drafts used up its right to test new ones.} (Found 2026-10-01
in the exploratory cells of amendment~(ab); fixed in amfs-internal \#803, cut
\code{post-branch-cap}, 03:17:37Z.) A repair branch is opened only while the agent has fewer
than ten open; the count included \code{test\_failed}, and a failed fix's branch is never
closed. A long-running agent with a normal Tier~1/Tier~2 failure rate fills its cap with dead
branches, as both support cells did within two and a half hours. After that every proposal is
staged branchless, gets no Tier~2 replay, and can never enter the canary queue. The loop had
degraded to propose-only without saying so: 29 fixes waiting without a branch, a canary slot
idle for the last 2.7 hours of a cell with 15 fixes ``queued''. The fix counts only the statuses
the policy can still move. The confirmatory cells were short enough (200 episodes, 4--8
proposals per cell) never to hit the cap, which is why this surfaced only when the horizon
doubled.
\end{enumerate}

\paragraph{The canary inside a cell.} Separately from the defects, no canary reached a decision
inside any 100-episode cell (K1--K4 in the readouts). A situated canary grades only
in-situation runs, and at \code{pct}=50 with a floor of 8 per arm it needs 16 in-situation
graded sessions after it starts, which a cell with 4--10 post-change exposures of one class
cannot supply. This is a property of the protocol, and the fleet-10 experiments are sized for it.

\section{Pending, and what we expect}
\label{sec:pending}

Every preregistered prediction and its verdict is in Table~\ref{tab:ledger}; this section
states what the verdicts changed. P10 (no fix drafted from a replay; no alias from a replay) is
met on \code{rsi-c5}: none of the 47 runs cited by 33 fix manifests carries a replay tag, while
134 of the 928 sessions sealed in the same window were replays. P11(a), that fewer than half of
proof-passing regime fixes would omit the conditional, was falsified 4 of 4, and the
falsification located where the conditional is lost: in the repair agent's draft, since the
proof removed 19 of 23 regime fixes and the four survivors were wholesale flips whose kept-half
replays passed because the replaying agent did not follow the entry. The drafting change that
followed (amendment (v)) is read by P11(a$'$), met on both the development runs (21 of 37) and
the confirmatory fleet-1 runs (27 of 39), with the class split in \S\ref{sec:gating}. P12--P14
were first read on \code{rsi-e2b-c6} (P12 not met, P13 falsified, P14 undefined), and finding 12
then showed that those canaries compared two untreated arms. The fleet-10 confirmatory cells ran
on \code{post-canary-visible} with the read-count predictions of amendments~(z), (z$'$) and
(z$''$) pre-specified; that run exposed finding~13 and is reported as measured. The confirmatory
read is the rerun on \code{post-replay-evidence} (\S\ref{sec:confirmatory}): the arm reads its
fix (P16, P13$''$ met), four of six canaries reach the floor on both arms (P12 met), one decides
(P13$'$ not met), nothing ships (P14, P15 without population). The exploratory run of
amendment~(ab) is the only place in this paper where a canary passes and a fix ships through it,
and it bears on no prediction.

\paragraph{The confirmatory scope, reduced before it ran.} Amendment (w), declared before any
confirmatory-seed cell and before the analysis freeze, set the confirmatory grid at seeds
37/41/59/73 on the two set-C families, both agent models, fleet~1 with every system and both
ablations, and fleet~10 with SenseLab and its two gate ablations: 22,400 episodes. Amendment
(y), declared the morning the runs launched, cut the fleet-10 part to SenseLab alone on GPT-5.5
after the second development fleet-10 run read the ablations the same way as the first, and
replaced the two blind coders with the author. The fleet-10 ablation comparison therefore has no
confirmatory read. The fleet-10 cells ran twice, after finding~12 and after finding~13

held-out-family design of amendment (l) lapses with it. The mixed-effects learning-curve model
named in the preregistration is not run, for the reasons given there. Not run at all, and
reported as not run: verdict sources (E3), the public track (E4), the A/A, adversarial,
reward-hacking and manifest-calibration probes, and the Managed Model rungs above L0 (E7). Each
is a claim this paper does not make. The adversarial probe~(b) has no injection path in the
harness; the one wrong fix the gate failed arose from the loop's own proposals and is not a
substitute for it.

\section{Related work}

\paragraph{Self-improvement.} Self-Refine~\cite{selfrefine} and STaR~\cite{star} improve a
model's outputs or weights from its own feedback within a task or a training run. The Gödel
machine lineage~\cite{godel,dgm} and AlphaEvolve~\cite{alphaevolve} modify the improver itself,
gated by a proof or a benchmark score, in a sandbox. The engine here is the deployed case: the
object it modifies is what every live agent acts on, the gate is live traffic, and the
contribution is the discipline (manifest, tiers of proof, staged exposure, reversibility, audit
trail) rather than the search. The ``fixed budget, held-out, sustained, generalising'' conditions
the preregistration adopts for any claim of self-improvement (E5) are the four conditions Weco
proposes for the ``net positive'' rung of its ladder~\cite{weco-ladder} and reports meeting with
AIDE$^2$~\cite{weco-aide2}. The ladder's rungs number the strength of a claim; the levels of this
paper number the stages of one loop. E5 has not run, and no rung is claimed.

\paragraph{Release engineering.} Canary release and controlled online experiments~\cite{kohavi}
are the discipline the loop borrows for level~1. A/A tests and look-schedule inflation are the
standard hazards, and the preregistration's A/A probe measures the empirical false-pass rate of
the canary's test under the schedule the harness uses.

\paragraph{Benchmarks.} $\tau$-bench and $\tau^2$-bench~\cite{taubench,tau2bench} evaluate
tool-using agents against a policy that stays fixed across tasks; our public track (E4) amends
the policy between passes. Continual-learning benchmarks for language models measure forgetting
in weights. The object here is what a deployed agent acts on, and the failure mode is
remembering.

\paragraph{Agent memory.} Reflexion~\cite{reflexion} and Voyager~\cite{voyager} write verbal
reflections and skills back for later episodes; Generative Agents~\cite{genagents} and
MemGPT~\cite{memgpt} manage a store with retrieval and summarisation; Mem0~\cite{mem0} and
Zep~\cite{zep} are production memory layers evaluated on conversational recall (LoCoMo,
LongMemEval~\cite{longmemeval}). All are evaluated on retrieving what was stored. None tests,
gates or reverts a change to the store, and none is measured on a change of the world after
storage. They are the substrate a self-improving engine operates on and the baselines it is
measured against here; our earlier report~\cite{senselab-cl} measured level~0 against these
designs under a regime change.

\section{Threats to validity}

\begin{itemize}[leftmargin=1.4em, itemsep=0.25em]
\item \textbf{Development seeds.} Every number in \S\ref{sec:results} is from two seeds on two
families, chosen for development. Nothing there is a confirmed difference, and the intervals say
so.
\item \textbf{One model, one effort level, on the development seeds.} GPT-5.5 at low effort.
Claude Opus 5 is half of the confirmatory grid, where every cell is model-aware.
\item \textbf{The benchmark's outcome is coarse.} The harness reports \code{success} for an
episode solved within three attempts. That is what a customer reports, and it hid finding 9 from
the proof set for two runs. The clean-success rule reads the attempts the agent already records;
a customer whose agent never records attempts gets no protection from it.
\item \textbf{The engine changed between runs.} Twelve defects were fixed in production during
the study (amfs-internal \#780--\#803, OSS \#454--\#455): one inside the fleet-1 confirmatory
window, two between the two fleet-10 confirmatory runs, and one (\#803) inside the last thirty
episodes of the exploratory cells, after which no fix was proposed. Every result carries its
cut. The changes are to the loop's evidence path, not to any threshold constant, which the
preregistration forbids. The one gate rule that changed, the canary's primary from superiority
to non-inferiority (finding 11), was preregistered with its falsifier before the run that tests
it.
\item \textbf{The loop's drafting cost is an estimate on the development seeds.} The repair
agent's spend is the account ledger's remainder spread over every draft (\S\ref{sec:cost}). The
confirmatory runs snapshot the ledger per cell and report the difference directly.
\item \textbf{Hand-coding.} The ``conditional'' share (P9(b), P11, P11(a$'$)) is one coder's
reading of the draft text against written instructions, and the coder is the author, not blind
to arm or verdict (amendment (y)). Every draft, the instructions, the coding and the key are
published so the reading can be redone.
\item \textbf{The harness routes the canary.} The production router runs in the MCP gateway; the
harness applies the same hash itself (parity-tested in CI) because it talks to the HTTP API.
\item \textbf{The context window is a strong baseline where it fits.} On \code{ci-fix} the whole
cell fits in 24k tokens and the window sees the change. It is the right comparison for short
horizons and unavailable for the 200-episode fleet, where it cannot fit.
\item \textbf{We built the system.} The preregistration, the amendments with their falsifiers,
the cut records and the ledger exist so that a reader can check what was predicted before each
run.
\end{itemize}
